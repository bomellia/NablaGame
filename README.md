# Basis Duel α — 1人用数式カードゲーム（GitHub Pages対応）

非公式のファン制作・技術試作版です。原作「ナブラ演算子ゲーム」を参考にしていますが、独自カード／独自ルールを含み、原作の公式実装ではありません。

## 起動

`index.html` を静的HTTPサーバーで公開すると遊べます。例えばプロジェクトディレクトリで:

```bash
python -m http.server 8000
```

その後 `http://localhost:8000` で開きます。JS ES Modules のため、ブラウザの `file://` 直開きでは動かない場合があります。

## GitHub Pagesに公開

リポジトリのルートに `index.html`, `style.css`, `ui.js`, `engine.js`, `symbolic.js`, `cards.js` を配置してpush。
GitHubリポジトリの **Settings → Pages → Build and deployment → Deploy from a branch → main / (root)** を選択します。
プロジェクトリポジトリならURLは `https://<username>.github.io/<repository>/` です。相対パスで読み込むため、リポジトリ名に依存しません。

## 搭載機能

- プレイヤー vs COM（難易度3段階、1手読みの評価）
- 両者3基底で開始、7枚手札、山札共用、手札補充、勝敗判定
- 原作のカード21種類／80枚の定義
- 独自拡張2種類（+C：5枚、x↦−x：3枚）。新規対戦時にON/OFF
- 微分、初等関数と特殊関数を含む不定積分、乗除、平方根、自然対数、基本逆関数、一部極限・上極限・下極限
- `Li(x)`（対数積分）、`Ei(x)`（指数積分）、`Si(x)` / `Ci(x)`（三角積分）、`erf(x)` / `erfi(x)`（誤差関数）、`FresnelS/C` などの積分公式と微分公式
- 解析的に原始関数が求められない場合も `∫(f(x))dx` として保持し、再微分で `f(x)` に戻す
- 極限の値を証明できない場合は `lim[x→…](f(x))` という未評価の形式的な基底で続行できる。数学的に存在しないと証明できる極限は使用不可
- 微分結果が大きくなる場合は `d/dx(f(x))` として保持でき、無理に膨大な項へ展開しない
- 定数 C ∈ {-2,-1,0,1,2} の選択。0への片側極限の選択
- 既知の初等関数の線形結合に対する線形従属判定
- 合法手のプレビュー、合法手の提案、COMの選択、操作履歴、端末保存
- **任意のターンにカード1枚を交換**（山札があれば可能、ターン消費）。自動計算が詰まっても続行可能
- 同じ因子の約分、積のべきの整理、sin/cosの奇偶性、限定的なロピタルの定理、複雑な式の新規生成を抑制
- 旧バージョンの保存状態に対する起動時の式整理

## 限界（重要）

- **完全なCASではありません。** 非初等関数の一部は既知の公式で扱いますが、すべての積分が特殊関数で閉じるわけではありません。未評価の積分・微分・極限は数式記号のまま保持します。極限が存在するか不明でも `lim[…]` という形式的基底として残せるのは **独自のゲーム規則** であり、数学的な存在証明ではありません。数学的に存在しないと判定できる極限は拒否します。
- 既知の多項式・三角関数・指数関数の線形結合でのみ線形従属を判定します。それ以外は構文が同一の場合だけ検出します。
- **約分は共通の実数定義域上での局所的な同値で判定します。** 例えば `x·x⁻¹` を `1` に整理しますが、元の式で x=0 が未定義だった情報は保存しません。基底の判定にもこの独自ゲームルールを適用します。厳密に定義域を保存する実装ではありません。
- 関数の定義域は独立オブジェクトとして追跡していません。`√(x²)` と `|x|` のような式の定義域や同値判定は未完成です。例外点・特異点の厳密な演算や、枝を意識した逆関数・合成関数の扱いには制限があります。
- `limsup` / `liminf` の具体値は `a sin(x)+b cos(x)+c` など証明可能な型に限定します。その他は形式的記号を維持します。
- 原作で可能な多枚数高階微積分・多段階の乗除、自由な正の定数倍、基底消滅時の生存選択、任意実数の積分定数、局所的な関数の一致判定は未実装です。
- 操作結果の係数は倍精度浮動小数点で保持します。`√π/2` 等の係数も近似表記であり、完全な厳密計算・厳密な定義域追跡は未実装です。
- **手札を1枚交換**できる独自ルールがあります。交換は山札があるときに限りターンを消費します。
- 原作と完全に同じゲームバランス・判定は保証しません。

## ディレクトリ

- `cards.js` — 枚数・種類・追加カードの宣言
- `symbolic.js` — 基本の数式AST・簡約・既知の線形従属
- `symbolic-extended.js` — 特殊関数、形式的な不定積分／極限、拡張微分／極限判定
- `engine.js` — 対戦状態、合法手列挙、ルール、COM
- `ui.js` — 表示・入力・セーブ
- `style.css` — モバイルUI
- `tests/` — 機能回帰テスト

## 今後の設計

次段階では数式を `expression + domain` の二層に分け、分岐・定義域・積分定数・基底生存選択を厳密化します。ゲーム判定は `validate → symbolic transform → domain check → dependence check → resolve → victory check` で分割し、必要に応じてCAS（例: SymPyをPyodide上で実行）を独立アダプタとして差し込めるようにするのがよいです。多数の自由操作を許す場合、計算時間・式爆発・COMの分岐増大を防ぐために深さ／計算量制限を設定します。
