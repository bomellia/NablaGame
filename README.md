# Basis Duel α — 数式カードゲーム（1人用 / GitHub Pages）

「ナブラ演算子ゲーム」から着想を得た、非公式のブラウザ対戦ゲームです。原作のカード構成をベースに、数式の自動計算・独自ルール・COM対戦を備えています。

## プレイ

GitHub Pages: https://bomellia.github.io/NablaGame/

`index.html` をHTTPサーバー上に配置すれば動作します（ES Modulesを使うため、`file://` 直開きは推奨しません）。

```
python -m http.server 8000
```

## v0.7の変更点

- **都度の数式簡約**：多項式と有理式の共通因子を約分し、`(x²−1)/(x−1) → x+1`、`x/x → 1` を扱います。`sin²x+cos²x → 1` など基本恒等式の正規化も追加。
- **定義域を忘れる独自ルール**：例えば `x/x` は即座に `1` と見なします。したがって、その後の `x→0` の極限も `1` です。元の式の除外点や定義域は追跡しません。
- **線形従属**：簡約後の式をもとに、共通する式や定数倍・線形和を係数ベクトルとして階数判定します。`tan x` と `2tan x`、また `1` と `sin²x+cos²x` を同一の基底方向と判定します。**一般の関数の同値性判定を完備したものではありません。**
- **初期基底**：両者に同じ、定数を含まない3基底を配ります。多項式（`x²` または `x³`）、三角（`sin x` または `cos x`）、指数（`e^x` または `e^{-x}`）の各カテゴリからランダム選択します。手札と操作カードは引き続きランダム。
- **極限カードの減量**：`lim +∞`、`lim −∞`、`lim 0` をそれぞれ2枚→1枚とし、`limsup`・`liminf` と合わせて5枚（元は8枚）に変更しました。基本デッキ77枚／拡張85枚。
- **積分の未評価式を禁止**：結果を対応済みの初等関数または特殊関数で表せない場合、操作を不成立とします。未評価積分記号（形式的な `I` ノード）を新規生成しません。
- **既知の積分形**：多項式、単純な有理式、線形引数の三角・指数、`tan`、`cot`、`sec`、`csc`、`sin²`/`cos²`、置換積分の一部、多項式×指数・三角関数の部分積分など。従来の `Li`・`Ei`・`Si`・`Ci`・`erf`・`erfi`・フレネル積分・双曲線積分も維持します。
- **LaTeXと表示順序**：加算項は次数の降順に並べ、数式をKaTeXで表示します。カードは小さくし、**相手の場→自分の場→選択カード・基底の全文プレビューと操作→手札**の順に変更。スマートフォンではページを縦スクロールせず、長いプレビュー数式は横スクロールできます。
- **COM探索**：1手の検討数を制限して、探索コストの増加を抑えました。

### 数学的な制約

**任意の初等関数について、初等関数による積分の可否を完全に判定し、その原始関数を必ず計算する機能は実現していません。** 現バージョンは、明示的な公式・置換・部分積分などで解が確定できる形を許可し、その他は拒否する保守的な仕様です。数学的に初等積分できる式でも、未対応の形では使用不可となり得ます。恒等式・任意の逆関数・定義域・不連続性の一般判定も未完成です。

「最も簡単な形」は数学的に一意ではないため、対応済みの等価変形と有理式の簡約を繰り返し適用する**正規化ルール**で実現しています。除外点を忘れることもゲーム固有のルールであり、通常の実解析とは異なります。

## v0.16：三角関数の周期的な極

- 共通の連続かつ無限遠で発散する実位相 u に対する c sin(u)^a cos(u)^b（整数指数）の上・下極限を、sin²(u) を変数として解析的に判定。tan/cot/sec/csc とその整数乗も対象。例：2 sin(x)/cos³(x) の下極限は −∞、上極限は +∞。通常の無限大極限とは区別する。

## v0.18：根号と冪の統合

- 同じ底の平方根・整数乗・分数乗を積や商でまとめる（x sqrt(x) → x^(3/2)、sqrt(x)/x → x^(-1/2) など）。単独の平方根と1/2乗の表現を揃えてから従属判定する。分数次数の項も降順表示する。異なる底の平方根を無条件に結合せず、sqrt(x²)=|x| を保持する。

## v0.19：連続演算と消去ボーナス

- 個別演算の確認時に「続けて演算」を選択すると、同一基底へ最大2演算。最初の結果で基底が消滅した場合は連続演算不可。全体演算・基底追加は連続演算の対象外。乗除算の材料は別途消費する。
- 相手の次元が減った場合、そのターンに1回だけ追加演算が可能（全体演算も可、基底追加・交換・再連鎖不可）。途中でターン終了可。手札補充はすべての演算終了後に一括実施。途中状態も保存し、従来の保存形式と互換。
- COMは2段階の攻撃を限定探索し、追加行動も実行する。探索上限があるため全コンボを網羅するものではない。

## v0.21：三角関数の商の和の極限

- 共通の連続かつ無限遠で発散する位相を持つ三角Laurent単項式の和について、sinまたはcosが0へ近づくときの最低指数・主要項の符号から正負の極を証明する。例：−12 sin(x) tan²(x)/cos³(x) −12 tan(x)/cos⁴(x) −4 sin(x)/cos³(x) の上極限は+∞、下極限は−∞。通常の無限遠極限は存在しない。
- 主要項の符号が相殺し得る場合は新規ルールで断定しない。片側の発散しか証明できない場合に反対側の極限を推測しない。一般の三角有理関数の有限極値・混合位相の判定は未対応。カード構成・保存形式は変更なし。


## v0.22：三角有理関数の極限

- tan(u/2) を用いて同一の連続・無限遠で発散する実位相 u と、その整数倍位相の sin/cos/tan/cot/sec/csc の有理式を多項式の商に変換。BigInt による有理係数、共通因子の除去、Sturm 列による実根分離、導関数の実根から上・下極限を計算する。有限の代数的極値は根を分離してから数値化する。極の符号・厳密なゼロを数値サンプリングで推測しない。
- 例：sec²(x)−tan²(x)=1、sin(x)/(2+cos(x)) の上下極限 ±1/√3、1/(1−sin(x)) の下極限 1/2・上極限 +∞。次数・整数係数の計算予算を超える式、非整数乗、一般の異なる位相、複素位相は従来の処理へフォールバック。カード構成・保存形式は変更なし。

- 位相が0へ近づく場合には半角変数の原点での局所極限にも適用し、0/0 の可除特異点と片側の発散を区別する。既存の単項式公式を優先し、有理式の上・下極限を小規模キャッシュしてCOM探索の重複計算を抑える。

## v0.32 — Function-graph seals

- 外周・刻みを維持し、中央の主紋様を関数の実数グラフに変更。基本関数・和・積・商・冪・合成を構文木から数値評価し、x∈[-π,π] のサンプルを共通の縦軸尺度に正規化。発散・未定義点・急な不連続候補では線を分断する。複素式は実部と虚部を異なる色で描く。未対応の特殊関数や評価予算を超える式は従来の抽象紋様へ戻す。数値描画は概形であり、定義域・不連続の厳密な判定ではない。

## v0.33 — Asymmetric openings and tactical cards

- 新規対戦では各3基底（多項式・三角・指数）を維持し、各カテゴリで異なる関数を配る。多項式は x²/x³、x²±x、x³±x、三角は sin/cos の1倍・2倍位相、指数は e^{±x}・e^{±2x} のペアから抽選し、各ペアの配分もランダム。先手優遇を意図しないが完全な公平性は未検証。
- 拡張デッキに関数 x³・|x| 各2枚、sinh x・cosh x 各1枚、演算 +・−・x↦x+C・1/f 各2枚（計14枚）を追加。拡張有効127枚、無効105枚。加減算は関数カードと併用し2枚消費、減算は選択順。平行移動はC=±1,±2。逆数は逆関数と区別。既存の演算・連鎖・消去ボーナスに統合。

## v0.35 — Selectable definite and improper integrals

- 片側積分カードは [0,+∞), (−∞,0], [1,+∞), [0,1], [x,+∞), (−∞,x] の6区間から選択。対称積分カードは (−∞,+∞), [−x,x], [−1,1] の3区間。各カード2枚、デッキ・セーブ形式は変更なし。従来の未指定操作は元の区間を使う。
- 既知の積分公式に加え、既存の不定積分と有限な端点値・片側極限を用いて計算。開半軸上の定義域・連続性を符号の保守的な構造判定で確認し、未確認の特異点・発散は操作不可。対称区間は原点の両側で独立に収束を要求し、主値による発散の相殺はしない。判定は十分条件であり、数学的に収束しても未対応の式はある。
- 変数端点の積分は連結した実数枝（右側なら x>0、左側なら x<0）で計算した式を使用する。定義域を保存しない既存のゲーム規約を維持。ガウス関数の尾積分は erfc ではなく 1−erf の形で表す。
- 区間選択・実行プレビュー・履歴・COMの合法手探索に対応。対称積分による奇関数の消去、定数化、尾積分による関数変換が可能。
